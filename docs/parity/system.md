## Push relay: what FCM delivery needs (`packages/notify-relay`, not changed here)

The relay seals `{ token, environment, ref }` (AES-256-GCM, AAD `opencode-notify-v2`) and on `/v2/notify/:sealed` sends one APNs alert: a fixed "OpenCode" / "New activity" plus the device-encrypted `box` (iOS 1ddd36b2; `/v1` now only sends the generic alert). Android registers with `environment: "fcm"` and an FCM registration token; today that is `400 invalid_request` and the app sends without a callback. (`packages/push-worker` holds only `node_modules`, no source.) The relay needs:

1. **Validation** (`seal.ts`, whose `isToken`/`isEnvironment` both `register` in `index.ts` and `unseal` check): `Environment` gains `"fcm"` (`isEnvironment`). FCM tokens are not hex: accept `/^[A-Za-z0-9_:-]{100,512}$/` when `environment === "fcm"` (so `isToken` takes the environment), keeping the hex rule for APNs. `register` (`index.ts`) must not lowercase an FCM token (`body.token.toLowerCase()`): FCM tokens are case-sensitive. The limiter key's `token.toLowerCase()` may stay (it only buckets). A ~160–200 char token keeps the sealed blob under `MAX_SEALED_CHARS` (1024) and the body under `MAX_REGISTER_BYTES`.
2. **Delivery** (new `fcm.ts`, chosen in `notify` by `environment`): FCM HTTP v1 `POST https://fcm.googleapis.com/v1/projects/<FCM_PROJECT_ID>/messages:send`, `authorization: Bearer <OAuth token>` from a service-account JWT (RS256, `scope https://www.googleapis.com/auth/firebase.messaging`, exchanged at `https://oauth2.googleapis.com/token`, cached in isolate memory ~50 min like the APNs JWT), `redirect: "manual"`, 10 s timeout. Body — data-only so the app builds the notification (visible session, badge count) whether it is running or not:
   `{ "message": { "token": <token>, "data": { "opencode": "{\"v\":2,\"ref\":<ref>,\"box\":<box>}" }, "android": { "priority": "HIGH", "ttl": "3600s", "collapse_key": <ref> } } }`: the same envelope the APNs payload carries (iOS 1ddd36b2), as a JSON string since FCM data values are strings, and no `data` for the generic `{}` push. No session text or ID travels in clear, so FCM sees what APNs sees (a 2,700-byte box fits FCM's 4 KB data limit).
3. **Outcomes**: 200 → `sent`; 404 `UNREGISTERED`, or 400 `INVALID_ARGUMENT` naming the token → `gone` (410 to the plugin); 401/403 → drop the cached OAuth token, `failed`; anything else → `failed` (502). Never log the token or response bodies.
4. **Config**: `FCM_PROJECT_ID` var; secrets `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY` (service account with the Firebase Cloud Messaging API). README's privacy section gains Google (FCM) next to Apple (APNs) as carrying the encrypted box.

Android switch-on after the relay deploys: ship the Firebase app's `google_app_id`, `gcm_defaultSenderId`, `google_api_key` and `project_id` string resources (the google-services plugin's output, or plain resources in `:app`). Firebase's init provider then creates the default app, `SessionNotifications.environment` becomes `"fcm"`, and the existing token wait / mint / callback / push-handler path runs unchanged. `firebase_messaging_auto_init_enabled` stays false: the token is fetched only when notifications are enabled and a send asks for a callback.
